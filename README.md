# BridgeRack

Живой хост плагинов для macOS в духе **Waves SuperRack SoundGrid**. Приложение принимает сигнал с одного аудиоустройства (например, Dante), обрабатывает его цепочками плагинов в рэках и отдаёт на другое устройство (например, USB-интерфейс).

```
 Dante Virtual Soundcard ──►  ┌──────────── BridgeRack ─────────────┐  ──► USB-карта
 (или любое CoreAudio-        │ ClockBridge: подстройка часов        │      (master clock)
  устройство: AVB, USB,       │ Рэк 1 [8 ch]: EQ ► Comp ► ... ► ...  │
  Thunderbolt, SoundGrid      │ Рэк 2 [2 ch]: ...                    │
  Driver, BlackHole ...)      │ Рэк N ...  + выравнивание задержек   │
                              └──────────────────────────────────────┘
```

## Возможности

| Что | Как сделано |
|---|---|
| Разные протоколы на вход и выход | Вход и выход открываются как **два независимых устройства**, даже с разными драйверами. Выход задаёт тактирование (master clock). Вход проходит через `ClockBridge`: это адаптивный ресемплер с PI-регулятором, который отслеживает дрейф часов (Dante/PTP против кварца USB-карты) и разницу частот (например, 44.1 → 48 кГц) |
| Плагины | **VST3** (везде), **AU** (macOS), **VST2** (если при сборке указан VST2 SDK, см. ниже), LV2 (Linux). AAX — нет, причина ниже |
| Интерфейс | Как у цифрового пульта: каналы стоят вертикальными полосами слева направо. Сверху вниз: название, входной патч, ручка гейна с индикатором перегрузки, вставки, MUTE и BYP, выходной патч, фейдер с консольной шкалой (+10…−∞ дБ, 0 дБ на 75% хода) и LED-метр |
| Каналы | Моно или стерео. Новая сессия открывается с 8 стереоканалами на входах и выходах 1–16 |
| Слоты | По умолчанию 8 на канал, минимум 4, максимум 16. Кнопка ▾ у слота открывает меню: копировать, вставить, копировать на другой канал, bypass, замена, перемещение. Слоты можно переставлять перетаскиванием |
| Маршрутизация | Матрица на каждый рэк: любой канал рэка можно взять с любого входа и отправить на любой выход. Выходы разных рэков на один канал суммируются |
| Задержка | Своя у каждого канала: плагин с задержкой задерживает только свой канал. Кнопка **PDC** внизу канала включает выравнивание, и выравниваются только каналы с включённым PDC. Задержка плагина показана прямо в слоте (в мс), задержка канала — внизу полосы. В строке состояния — общий путь: вход, мост, выход |
| Выбор плагинов | Меню по категориям (EQ, Dynamics, Reverb, Delay, Mastering и т. д.) с цветом категории, последние использованные плагины сверху, отдельный список по производителям |
| Перенос плагинов | Перетащите слот на любой канал. Если слот занят, плагины меняются местами. С зажатым Option/Alt делается копия |
| Снапшоты | Полное состояние всех рэков: плагины, их настройки, роутинг, гейны. Если в слоте уже стоит тот же плагин, при вызове он не перезагружается, а только получает новое состояние, поэтому переключение быстрое. Переключать можно стрелками ← → |
| Сессии | Файлы `.bridgerack` (Cmd+S / Cmd+O), автосохранение раз в минуту и при выходе. При запуске восстанавливается последняя сессия |
| Надёжность | Если устройство пропало (выдернули кабель, перезапустили DVS), приложение раз в 3 секунды пытается открыть его заново. Плагины, которые падают при сканировании, попадают в чёрный список |
| Мониторинг | Метры входа и выхода каждого рэка, загрузка CPU, общая задержка, состояние моста (LOCKED/SYNCING, дрейф в ppm, количество выпадений) |

## Протоколы: как подключить

BridgeRack работает с любым устройством, которое macOS видит как аудиоустройство (CoreAudio):

- **Dante**: Dante Virtual Soundcard (DVS) или Dante Via. DVS отображается как устройство с числом каналов до 64×64.
- **AES67**: DVS в режиме AES67 или Merging Virtual Audio Device.
- **AVB**: встроенная поддержка macOS, настраивается в Audio MIDI Setup → Network Device Browser.
- **USB, Thunderbolt, FireWire, MADI**: любые интерфейсы, включая MADI-карты (RME и др.).
- **SoundGrid**: Waves SoundGrid Driver тоже представляется как CoreAudio-устройство.
- **Маршрутизация между программами**: BlackHole или Loopback.

Пример «Dante на вход, USB на выход»: **Audio I/O** → Input: `CoreAudio / Dante Virtual Soundcard`, Output: `CoreAudio / <USB-карта>` → **Apply**. В строке состояния появится `Clock bridge: LOCKED +12.3 ppm`.

Если в обе стороны выбрано одно и то же устройство, мост не используется: устройство работает как обычное дуплексное, без лишней задержки.

### Задержка моста

Мост сам подстраивает размер буфера: наблюдает реальный джиттер устройств и уменьшает запас, пока он не нужен. В тестах это экономит 30–57% задержки моста. Если всё же случится выпадение, мост измерит, на сколько замолчал входной драйвер, сразу расширит буфер до этой паузы (не больше 250 мс) и больше не опустится ниже этого уровня. Программные драйверы вроде Dante Virtual Soundcard иногда замирают на десятки миллисекунд: в тестах с паузами по 40 мс мост теряет 3–4 блока при подстройке, а дальше работает без выпадений. Режим можно выключить в Audio I/O (**Adaptive buffer**).

Мост добавляет примерно `буфер выхода + половину буфера входа + safety`. При 64/64 сэмплах на 48 кГц это около 3–4 мс. Параметр **Bridge safety buffer** в окне Audio I/O увеличивает запас, если слышны выпадения.

## Как измерить задержку своих плагинов

`BridgeRackProbe` (лежит рядом с приложением в архиве сборки) загружает установленные плагины тем же движком, что и BridgeRack, и показывает по каждому: заявленную задержку, реально измеренную по импульсу и нагрузку на CPU. В конце он прогоняет все найденные плагины последовательно через один канал BridgeRack.

```bash
chmod +x BridgeRackProbe
xattr -d com.apple.quarantine BridgeRackProbe
./BridgeRackProbe "F6" "eMo D5" "Stabilizer"
./BridgeRackProbe --block 128 "F6"        # другой размер буфера
```

Сначала один раз просканируйте плагины в самом BridgeRack: Probe берёт тот же список.

## Почему нет AAX

AAX — закрытый формат Avid. Хостить AAX-плагины разрешено только хостам, одобренным Avid (Pro Tools, VENUE). Публичного SDK для хостинга нет, а сами плагины защищены PACE/iLok и в чужом хосте не запустятся. **Практически у всех AAX-плагинов есть VST3- или AU-версия от того же производителя** (включая Waves: WaveShell-VST3/AU), и BridgeRack загружает их.

## VST2

Steinberg больше не распространяет VST2 SDK. Если у вас есть его копия (папка с `pluginterfaces/vst2.x`), соберите проект так:

```bash
cmake -S . -B build -DBRIDGERACK_VST2_SDK_PATH=/путь/к/vst2sdk
```

## Сборка на Mac

Нужны Xcode Command Line Tools (`xcode-select --install`) и CMake (`brew install cmake`).

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DCMAKE_OSX_ARCHITECTURES="arm64;x86_64"
cmake --build build --config Release -j 8
./build/BridgeRackTests                                   # тесты движка
open build/BridgeRack_artefacts/Release/BridgeRack.app
```

JUCE 9.0.3 скачивается автоматически при первой конфигурации.

### Готовая сборка через GitHub Actions

При каждом push workflow `.github/workflows/build.yml` собирает universal-приложение (Apple Silicon + Intel) на macOS-раннере и выкладывает `BridgeRack-macOS.dmg` и `.zip` в Artifacts. Приложение подписано ad-hoc и не нотаризовано, поэтому при первом запуске macOS его заблокирует. Варианты:

```bash
xattr -dr com.apple.quarantine /Applications/BridgeRack.app
```

или правый клик по приложению → Open.

При первом запуске macOS спросит доступ к микрофону: он нужен для получения входного сигнала. Без него все входы молчат, и BridgeRack покажет предупреждение с кнопкой перехода в настройки.

**Если входы перестали работать после обновления**, сбросьте разрешение и перезапустите приложение. macOS спросит доступ заново:

```bash
tccutil reset Microphone org.bridgerack.app
```

Начиная с версии 0.3 подпись приложения устроена так, что разрешение сохраняется между обновлениями.

## Как пользоваться

1. **Plugins** → Options → *Scan for new or updated VST3 / AudioUnit plug-ins*.
2. **Audio I/O**: выбрать входное и выходное устройства → Apply.
3. **+ Rack**: выбрать число каналов. Новый рэк автоматически подключается к следующим свободным каналам.
4. Клик по пустому слоту вставляет плагин, клик по занятому открывает редактор. Правый клик открывает меню: bypass, замена, удаление, перемещение. Внутри рэка плагины можно перетаскивать между слотами мышью.
5. **IN / OUT** открывает матрицу маршрутизации рэка.
6. **Store** сохраняет снапшот, кнопки **< >** или клавиши ← → переключают снапшоты.

## Устройство кода

```
src/engine/ClockBridge.*   мост между доменами тактирования (lock-free FIFO + адаптивный ресемплер + PI-регулятор)
src/engine/Rack.*          рэк: роутинг, гейны, цепочка слотов, PDC-задержка, метры
src/engine/RackSet.*       набор рэков, суммирование выходов, выравнивание задержек, разбиение больших блоков
src/engine/AudioEngine.*   открытие одного или двух устройств, аудиоколбэк, автопереподключение
src/engine/PluginHost.*    форматы плагинов, список найденных плагинов, создание экземпляров
src/engine/Session.*       сериализация рэков, снапшоты, файлы сессий
src/ui/*                   интерфейс (JUCE)
tests/TestMain.cpp         тесты движка без GUI и аудиоустройств
```

Аудиопоток не ждёт блокировок: каждый рэк при обработке только *пробует* взять свою блокировку. Если рэк в этот момент перестраивается (меняется число каналов или загружается состояние), он пропускает один блок, а остальные рэки продолжают звучать. Плагины загружаются и подготавливаются вне аудиопотока, а в цепочку подменяются только указатели.

## Что проверено

- **Тесты движка** (`BridgeRackTests`):
  - мост при дрейфе часов +100, −80 и +30 ppm с разными размерами блоков и джиттером колбэков: ноль выпадений, регулятор сходится к реальному дрейфу;
  - конвертация 44.1 → 48 кГц: частота тестового синуса на выходе точная, разрывов нет;
  - маршрутизация и суммирование, mute, bypass, разбиение больших блоков;
  - выравнивание задержек между рэками;
  - сохранение и восстановление сессий, вызов снапшотов без перезагрузки плагинов.
- **Linux (JACK)**: приложение собрано и запущено. Проверены сканирование, загрузка и редакторы реальных VST3-плагинов (LSP), рэки, роутинг, снапшоты и автосохранение.
- **Не проверено**: сборка под macOS и работа с реальным оборудованием Dante и USB. Для этого нужен Mac.

## Планы

- Multi-mono и multi-stereo: несколько связанных экземпляров стерео-плагина на многоканальном рэке, как в SuperRack.
- Переключение снапшотов по MIDI Program Change и OSC.
- Параллельная обработка рэков на нескольких ядрах.
- Сканирование и запуск плагинов в отдельном процессе, чтобы падение плагина не роняло хост.
- Сайдчейн-входы плагинов из любого канала.
- Резервирование: автоматический переход на запасное устройство (например, Dante Secondary).

## Лицензия

Проект использует JUCE, который распространяется под AGPLv3 или по коммерческой лицензии JUCE. Для личного использования и открытого кода подходит AGPLv3. Для распространения закрытой версии нужна коммерческая лицензия JUCE.

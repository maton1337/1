# BridgeRack: история разработки (из чата с Claude)

Краткая запись разговора, в котором был создан проект: что просили, что решили, что сделано и что осталось.

## 1. Исходный запрос

Нужно приложение для macOS по типу **Waves SuperRack SoundGrid**:
- принимать сигнал по одному протоколу и отдавать по другому (например, вход по Dante, выход на USB-карту);
- подключать плагины VST2, VST3 и AAX;
- не меньше 4 слотов под плагины;
- выбираемое число каналов.

## 2. Ключевые решения

| Вопрос | Решение и причина |
|---|---|
| Технология | C++ и JUCE 9.0.3, сборка через CMake. JUCE скачивается автоматически |
| Разные протоколы на вход и выход | Вход и выход открываются как **два независимых CoreAudio-устройства**. Тактирование задаёт выход. Вход проходит через `ClockBridge`: lock-free FIFO, адаптивный ресемплер Лагранжа и PI-регулятор уровня буфера, который компенсирует дрейф часов (Dante/PTP против кварца USB) и разницу частот |
| Dante | Через Dante Virtual Soundcard: macOS видит его как обычное аудиоустройство. Встроить Dante напрямую нельзя без лицензии Audinate. Так же подключаются AVB, AES67, MADI, драйвер SoundGrid и BlackHole |
| AAX | **Невозможно.** Avid разрешает хостить AAX только своим программам, а плагины защищены PACE/iLok. У большинства AAX-плагинов есть версии VST3 или AU, включая Waves |
| VST2 | Только если при сборке указан старый VST2 SDK: `-DBRIDGERACK_VST2_SDK_PATH=...` |
| Сборка под Mac | Через GitHub Actions на macOS-раннере. Получается universal-сборка (arm64 + x86_64) в виде `.dmg` и `.zip` с ad-hoc подписью |

## 3. Версия 1 (ветка `main`, коммит 6bcb7e7)

- Рэки с числом каналов от 1 до 64 и слотами от 4 до 16 (по умолчанию 8). Bypass для каждого слота, перестановка перетаскиванием.
- Матрица маршрутизации для входа и выхода каждого рэка, выходы на один канал суммируются.
- Выравнивание задержек между рэками (PDC).
- Снапшоты: полное состояние, быстрый вызов без перезагрузки уже загруженных плагинов.
- Сессии `.bridgerack`, автосохранение раз в минуту и при выходе.
- Автоматическое переподключение пропавшего устройства.
- Тесты движка в `tests/TestMain.cpp`:
  - дрейф ±100 ppm без выпадений;
  - конвертация 44.1 → 48 кГц без разрывов;
  - роутинг, PDC, сессии.
- Проверено на Linux (JACK) с реальными VST3-плагинами LSP. Сборка под macOS в CI прошла.

## 4. Версия 2 (ветка `console-ui`)

Пожелания пользователя:
- рэк не больше 2 каналов;
- 8 рэков по умолчанию;
- интерфейс как у пульта: вертикальные полосы, сверху гейн, снизу логарифмический фейдер;
- стиль как у консоли «S5000»;
- копирование плагина из слота в слот через кнопку опций;
- более узкие слоты;
- разобраться с задержкой: 4 плагина дают около 100 мс.

Сделано:
- Каналы только моно или стерео (`kMaxChannelsPerRack = 2`). Новая сессия открывается с 8 стереоканалами на входах и выходах 1–16.
- `ChannelStrip` (заменил горизонтальный `RackRow`). Сверху вниз:
  - scribble strip с цветом канала;
  - MONO/ST и входной патч;
  - ручка гейна ±24 дБ с LED-кольцом и индикатором перегрузки;
  - компактные слоты вставок;
  - MUTE / BYP / меню канала;
  - выходной патч;
  - фейдер по консольному закону (+10…−∞ дБ, 0 дБ на 75% хода, `FaderLaw` в `LookAndFeel.cpp`) и сегментный LED-метр.
- Кнопка ▾ у слота открывает меню: копировать, вставить, «Копировать на канал ▸», bypass, замена, удаление, перемещение вверх и вниз. Копия переносит плагин вместе с настройками.
- Задержка:
  - в строке состояния разложена на вход, мост, вставки и выход;
  - слоты плагинов, которые добавляют задержку, отмечены жёлтой полоской;
  - внизу каждого канала показана задержка его вставок в мс;
  - Align latency по умолчанию выключен.
- Вывод по 100 мс: задержку дают сами плагины (lookahead, linear phase) и большие аудиобуферы, а не движок. Пользователя попросили прислать скриншот строки состояния.
- Стиль: сделан общий вид цифровой консоли. Модель «S5000» не уточнена, пользователя попросили прислать фото.

## 5. Версия 3 (ветка `console-ui`, коммит 771d9e9)

Жалоба пользователя: большая задержка от плагинов Waves F6, Waves eMo D5 и iZotope Ozone Stabilizer.

Пожелания:
- категории в меню выбора плагинов;
- задержка не должна распространяться на все каналы, только на свой;
- уменьшить задержку в целом;
- drag-and-drop плагинов между каналами.

Сделано:
- **Задержка для каждого канала отдельно.** Кнопка **PDC** в каждой полосе; выравниваются только каналы с включённым PDC. Старый глобальный флаг `latencyCompensation` в сессиях игнорируется. Вероятная причина жалобы: в v1 выравнивание было включено по умолчанию и сохранилось в автосохранении.
- **Адаптивный буфер моста** (`ClockBridge`, `Settings::adaptive`): буфер сужается под наблюдаемый джиттер. В симуляции задержка моста ниже на 30–57%.
- **Меню плагинов по категориям** (`src/ui/PluginMenu.*`), раздел Recent, список по производителям. Слот показывает цвет категории и задержку плагина в мс.
- **Drag-and-drop слотов между каналами**: занятые слоты меняются местами, Option/Alt делает копию. Методы `Rack::takeSlot` и `Rack::putSlot`.
- **`BridgeRackProbe`** (`tests/Probe.cpp`): CLI, который загружает установленные плагины движком BridgeRack и выводит заявленную и измеренную задержку, CPU, а также задержку всей цепочки через канал. Проверено на LSP: рэк не добавляет ни одного сэмпла сверх задержки плагинов.
- Waves и iZotope в облачном Linux протестировать нельзя. Нужен Mac пользователя.

## 6. Версия 4 (ветка `console-ui`, коммиты 6708fb6…921c33d)

Жалобы пользователя: перестали приходить входные сигналы. Плюс просьба об иконке с буквами BR.

Найдено и исправлено две вероятные причины:
1. **Разрешение на микрофон в macOS.** Ad-hoc подпись менялась с каждой сборкой, и разрешение терялось.
   - `src/platform/MicPermission.mm` (AVFoundation) проверяет и запрашивает доступ при запуске, при отказе показывает окно с кнопкой в настройки.
   - CI подписывает приложение с designated requirement `identifier "org.bridgerack.app"`, чтобы разрешение сохранялось между обновлениями.
   - Если доступ уже потерян: `tccutil reset Microphone org.bridgerack.app`, затем перезапуск.
2. **Мост при «рваных» драйверах.** Сквозной тест с виртуальными устройствами (`tests/FakeDevices.h`) показал на macOS-раннере паузы колбэков до 40 мс: мост постоянно перезаполнялся, вход пропадал. Было: фиксированный буфер — 215 выпадений за 8 с, старый адаптивный — 88. Теперь при выпадении мост измеряет реальную паузу входа и расширяет буфер до неё (потолок 250 мс): 3–4 выпадения при подстройке, дальше 0. Переключатель **Adaptive buffer** в окне Audio I/O.

Ещё:
- В строке состояния предупреждения: NO INPUT SIGNAL, INPUT BLOCKED, NO INPUT DEVICE.
- Иконка `resources/icon.png`: BR и LED-метр, генератор `resources/make_icon.py`.
- CI выводит упавшие проверки и строки `[info]` как аннотации GitHub, потому что логи CI из облачного контейнера недоступны.

## 8. Следующий шаг: тестирование на Mac пользователя

Работа переносится в сессию Claude на Mac пользователя: Claude Desktop с вкладкой Code и включённым Computer use. План:
1. Собрать проект локально (`cmake`, Xcode CLT) и запустить `./build/BridgeRackTests`.
2. Запустить `./build/BridgeRackProbe "F6" "eMo D5" "Stabilizer"` и сравнить заявленную и измеренную задержку и CPU (сначала один раз просканировать плагины в BridgeRack).
3. Открыть BridgeRack, проверить разрешение на микрофон, вход DVS и выход USB, метры и строку состояния (`Bridge LOCKED`, задержки по частям).
4. Поставить F6, eMo D5 и Stabilizer в один канал и посмотреть задержку канала. Убедиться, что остальные каналы без задержки, если PDC выключен.
5. По результатам: оптимизация, перенос `console-ui` в `main`.

## 10. Как продолжить локально

```bash
git clone https://github.com/maton1337/1 BridgeRack
cd BridgeRack
git checkout console-ui
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j 8
./build/BridgeRackTests
open build/BridgeRack_artefacts/Release/BridgeRack.app
```

В Claude Desktop (вкладка Code) откройте эту папку и попросите: «прочитай docs/CHAT_HISTORY.md и продолжим тестирование с моими плагинами».
